## 1. Executive Summary

Batch 3 successfully delivers the **Customer Portal** and initial **Security Baseline** hardening for ODS Global Network:
1. **Security Architecture & RBAC**:
   - Eliminated the default seeded test admin account from migration 009 via migration `012`.
   - Created standalone admin provisioning CLI script (`Backend/scripts/create-admin.js`).
   - Created limited DB role provisioning script (`Backend/scripts/setup-limited-db-user.sql`).
   - Built server-side authentication & RBAC middleware (`Backend/src/middleware/auth.js`) enforcing `requireAuth` and `requireRole`.
   - Enforced strict startup validation requiring non-placeholder `JWT_SECRET` (at least 32 chars) across all environments without fallbacks.
   - Built relational audit trail table `audit_logs` (migration `013`) and `auditService.js` logging all login, registration, password change, and profile update events.
2. **Customer Endpoints & Address Integration**:
   - `GET /api/customer/profile`: Retrieves customer details and primary polymorphic address.
   - `PUT /api/customer/profile`: Updates customer profile fields and updates-or-inserts address records in `addresses`.
   - `POST /api/customer/change-password`: Validates non-empty current password, enforces 8–128 character complexity for new password, updates bcrypt hash, and resets lockout.
   - Enhanced registration transaction to persist address details for customer accounts.
3. **Frontend Customer Portal UI & Service**:
   - Built `Frontend/src/services/customerService.ts` with structured error handling.
   - Enhanced `AuthContext.tsx` with `updateUser` for instantaneous topbar synchronization.
   - Refactored `CustomerDashboard.tsx` with responsive, accessible tab navigation:
     - **Overview**: Honest metric cards ("Not available yet" for unbuilt services, "Active" for verified status) and quick shortcuts.
     - **My Profile**: Live editable profile form with read-only email protection.
     - **Security**: Password change form with interactive strength meter.
     - **Appointments / Gift Cards / Notifications**: Honest empty states with "Not available yet" copy and zero internal batch references.

## 4. Not Verified (Items for Manual/Future Verification)

The following items are explicitly documented as unverified in local automated tests:
1. **Old sessions stay valid after password change**: In MVP, JWT session cookies have a 1-day expiration without a centralized Redis token revocation blacklist. Invalidation on password change is deferred to the Advanced Auth/Sessions batch.
2. **No rate limiting on the password change endpoint per-user**: Rate limiting is currently applied per-IP (30 req / 15 min on `/api/customer`); identifier-based rate limiting on password change will be expanded in the Security Hardening milestone.
3. **Database connection as superuser in production**: Backend currently connects using local superuser credentials. Production requires running `scripts/setup-limited-db-user.sql` to configure the restricted `ods_app_user`.
