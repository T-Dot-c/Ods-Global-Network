### 5. States and Flows
1. **Initial State (Token Present)**: Card displays top badge `"Wanaw Reset Password"`, password input, and submit button.
2. **Initial State (Token Missing)**: No upfront check or guard is performed when the page loads without a `?token=` parameter. The user is still presented with the form; clicking submit sends `POST .../reset-password/null`, which fails at the backend.
3. **Submitting / Loading State**: None. No loading spinner or disabled state is applied.
4. **Validation Error State (HTTP 400)**: Displays green styled paragraph text with the error message: `<p className="text-green-600 text-center mb-4">{message}</p>` reading `"Invalid or expired token"`. *(Defect: Notice the legacy component renders backend error messages in green text due to reusing `message` state).*
5. **Server Error State (HTTP 500 / Network)**: Displays `"Something went wrong."` in green text.
6. **Success State (HTTP 200)**: Displays `"Password reset successful"` in green text, clears password input (`setPassword("")`). The user remains on the page indefinitely with no automatic redirect to `/login`.
7. **Post-Submission Navigation**: User must manually click `"Login"` link (which performs a full browser reload via native `<a href="/login">` rather than SPA client routing).

### 6. Data and Backend
- **Endpoint**: `POST ${BASE_URL}/auth/reset-password/${token}` (configured in [`resource/server/routes/auth.js:L116`](file:///d:/Ods%20Global/Source%20Code/Ods-Global-Network/resource/server/routes/auth.js#L116)).
- **Request Parameters**: URL route param `:token` extracted from client query string `?token=...`.
- **Request Payload**: JSON object `{ "password": string }`.
- **Response Payload**:
  - HTTP 200: `{ "msg": "Password reset successful" }`
  - HTTP 400: `{ "msg": "Invalid or expired token" }`
  - HTTP 500: `{ "msg": "Server error" }`
- **Backend Operations ([`authController.js:L622-L646`](file:///d:/Ods%20Global/Source%20Code/Ods-Global-Network/resource/server/controllers/authController.js#L622-L646))**:
  1. Executes query: `SELECT * FROM users WHERE resetToken = ? AND tokenExpire > ?` passing `[token, Date.now()]`.
  2. If matching record not found or expired, returns HTTP 400 `{ msg: "Invalid or expired token" }`.
  3. Hashes new password: `await bcrypt.hash(password, 10)` (Defect: Uses 10 rounds; System Directive §8 requires 12 rounds minimum).
  4. Updates database: `UPDATE users SET password = ?, resetToken = NULL, tokenExpire = NULL WHERE id = ?`.
  5. Does NOT invalidate existing user sessions or issue an audit log entry.
  6. Returns HTTP 200 `{ msg: "Password reset successful" }`.

### 8. Security Observations (Scope Section 10 & Directive §8 / §17)
1. **URL Query Token Exposure**: Passing the secret token in `?token=` violates System Directive §8 ("Zero Token Exposure: Never pass tokens in URL query parameters").
2. **Weak Bcrypt Factor**: Uses `bcrypt.hash(password, 10)` instead of the project mandate of 12 rounds minimum.
3. **No Password Confirmation / Confirmation Mismatch Check**: Only a single password field is provided, making typographical errors unrecoverable without restarting the flow.
4. **No Password Complexity Policy**: Any non-empty string (even 1 character) is accepted and hashed by the backend.
5. **No Session Revocation**: Updating the password does not revoke active session cookies or JWT tokens on other devices.
6. **No Token Invalidation on Multiple Failures**: An attacker could attempt brute-forcing against the reset endpoint if short tokens were used (though 32 random hex bytes mitigates brute-forcing the token itself).
7. **UI Error Masking Defect**: Error messages are rendered inside `<p className="text-green-600">`, creating confusing feedback for users.
